# Milestone v1.1: Public frontend API responses

**Status:** ✅ SHIPPED 2026-07-23
**Phases:** 5-8
**Total Plans:** 8

## Overview

This milestone replaced the legacy public PHP data sources with backend-owned JSON endpoints for the public frontend. The backend now serves the home-page catalog, episode detail data, public people/site metadata, and supporters data through stable `/v1/public/*` contracts.

Closeout note: this milestone was archived as an override closeout because the GSD phase artifact history drifted behind the implemented code. Phase 5 retains plan summaries and an executable validation path; Phases 6-8 were reconciled from the shipped code, OpenAPI surface, and feature documentation on 2026-07-23.

## Phases

### Phase 5: Public Episodes Catalog Endpoint

**Goal**: Replace the legacy public catalog response with a backend JSON endpoint for the home page.
**Depends on**: Phase 4
**Plans**: 2 plans

Plans:

- [x] 05-01: Define and document the catalog response contract from current frontend usage.
- [x] 05-02: Implement the public catalog route, mapping, and verification.

**Details:**
- `GET /v1/public/episodes` returns published episodes only in newest-first order.
- Catalog items expose frontend-ready fields including `episodeId`, `title`, `summary`, `pubDate`, `guests`, `pageUrl`, `audioUrl`, `coverUrl`, and `trailerUrl`.
- Validation now runs through `npm run verify:public-episodes`, which invokes the shipped route handler directly and verifies the Phase 5 contract without depending on sandboxed localhost networking.

### Phase 6: Public Episode Detail Endpoint

**Goal**: Serve episode-page data from a dedicated backend JSON endpoint.
**Depends on**: Phase 5
**Plans**: 2 plans

Plans:

- [x] 06-01: Define the episode-detail contract and field mapping from current frontend usage.
- [x] 06-02: Implement the public episode-detail route and verification.

**Details:**
- `GET /v1/public/episodes/:episodeId` is implemented in the backend and documented in OpenAPI.
- The detail contract includes summary, playback/download URLs, citations, credits, and embed-related fields required by the current episode page.
- Unpublished or missing episode IDs return a clear not-found response.

### Phase 7: Public People and Site Metadata Endpoints

**Goal**: Expose shared people/contact and site metadata contracts for public pages.
**Depends on**: Phase 6
**Plans**: 2 plans

Plans:

- [x] 07-01: Implement the public people/contacts contract and route.
- [x] 07-02: Implement the public site metadata contract and route.

**Details:**
- Public routes exist for `/v1/public/about`, `/v1/public/contact`, `/v1/public/social`, `/v1/public/contacts`, and `/v1/public/site-config`.
- The public contacts contract is normalized for frontend author/contact resolution.
- Shared site metadata now comes from backend-owned configuration instead of legacy frontend constants.

### Phase 8: Public Supporters Endpoint and Verification

**Goal**: Replace the legacy supporters source and finalize public API docs and validation.
**Depends on**: Phase 7
**Plans**: 2 plans

Plans:

- [x] 08-01: Implement the public supporters contract and route.
- [x] 08-02: Document and verify the full public endpoint suite.

**Details:**
- `GET /v1/public/supporters` is implemented with `supporters` terminology instead of `patreon`.
- The public endpoint suite is documented in `src/docs/openapi.ts` and `docs/features/005-public-frontend-api/README.md`.
- Backend verification for this milestone includes `npm run typecheck`, `npm run build`, and `npm run verify:public-episodes`.

## Milestone Summary

**Decimal Phases:**

- None

**Key Decisions:**

- Replace legacy public PHP responses with backend-owned JSON endpoints.
- Keep public data split across distinct endpoints rather than a single aggregate payload.
- Use the live site and `dragaocareca_frontend` repo as the compatibility reference for public contracts.
- Add a repo-native verification script for the public catalog route so validation does not depend on sandboxed loopback networking.

**Issues Resolved:**

- Removed frontend dependence on legacy PHP episode catalog responses.
- Added backend-owned episode detail, site metadata, contacts, social, and supporters contracts.
- Established stable OpenAPI coverage for the public endpoint suite.

**Issues Deferred:**

- GSD artifact history for Phases 6-8 was not reconstructed into per-phase directories before closeout.
- A fuller end-to-end public API verification workflow beyond Phase 5 remains future work if stricter phase-by-phase evidence is needed.

**Technical Debt Incurred:**

- Milestone closeout relied on reconciled code and docs for Phases 6-8 instead of complete original GSD execution artifacts.
