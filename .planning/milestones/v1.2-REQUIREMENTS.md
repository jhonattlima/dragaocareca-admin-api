# Requirements Archive: dragaocareca-admin-api v1.2

**Archived:** 2026-07-23
**Milestone:** v1.2 Episode AI authoring API
**Closeout Type:** Standard closeout
**Core Value:** Serve the public frontend with stable backend-owned data contracts so page rendering no longer depends on legacy PHP responses or client-side reconstruction rules.

## Completed Requirements

### Summary Generation

- [x] **SUMM-01**: The backend can generate a suggested summary using only the episode transcript as source input.
- [x] **SUMM-02**: Suggested summaries are produced in Portuguese-BR and stay short enough for publish-ready episode metadata.
- [x] **SUMM-03**: Summary generation does not overwrite the saved episode summary automatically.

### Workflow and Runtime

- [x] **FLOW-01**: Summary generation runs sequentially inside `admin-api` to fit the 4 GB VPS constraint.
- [x] **FLOW-02**: Summary generation only starts when a transcript file already exists for the episode draft.
- [x] **FLOW-03**: Generated summary text is stored as draft suggestion data inside the episode folder for later reuse.

### Admin API

- [x] **API-01**: A protected backend endpoint can trigger or refresh summary suggestion generation for an episode.
- [x] **API-02**: A protected backend endpoint can return the current summary suggestion and generation status for an episode.
- [x] **API-03**: The admin API exposes generation failures and readiness state clearly enough for later frontend integration.

### Verification and Operations

- [x] **OPS-01**: Summary generation model/runtime selection is configuration-driven inside the backend.
- [x] **OPS-02**: Verification covers build/type safety plus an executable backend check of the summary-suggestion workflow.
- [x] **DOC-01**: Backend docs describe the summary-suggestion flow, storage location, and operational constraints.

## Requirement Outcomes
