## Directory Purposes

**`src/`:**
- Purpose: all application source code
- Contains: Express app, routes, services, DB access, scripts, workers
- Key files: `src/server.ts`, `src/app.ts`, `src/config/env.ts`
- Subdirectories: route/service/repository split rather than by feature slices

**`data/`:**
- Purpose: persistent runtime artifacts and reference content
- Contains: SQLite DB files, feed snapshots, generated cover mosaic, legacy `all_episodes.json`
- Key files: `data/database/dragaocareca-admin.sqlite`, `data/feed/reference-feed.xml`, `data/generated/cover-mosaic.svg`
- Subdirectories: `database/`, `feed/`, `generated/`

**`docs/`:**
- Purpose: durable project and feature documentation
- Contains: `docs/SDD.md`, `docs/FEATURES.md`, `docs/VPS-SETUP.md`, feature READMEs/PLANs
- Key files: `docs/SDD.md`
- Subdirectories: `docs/features/`

**`scripts/`:**
- Purpose: machine/bootstrap helpers outside the application runtime
- Contains: shell scripts for VPS dependency install/bootstrap
- Key files: `scripts/bootstrap-vps.sh`, `scripts/install-vps-deps.sh`

## Key File Locations

**Entry Points:**
- `src/server.ts`: process bootstrap and worker startup
- `src/app.ts`: Express application composition
- `src/scripts/import-legacy-episodes.ts`: one-off import entry point

**Configuration:**
- `src/config/env.ts`: central runtime config object
- `package.json`: scripts and dependency manifest
- `tsconfig.json`: TS compiler behavior
- `.env.example`, `.env.dev`, `.env.production`: environment files

**Core Logic:**
- `src/routes/`: HTTP endpoints
- `src/services/`: feed, metrics, notification, media, transcription logic
- `src/database/repositories/episode.repository.ts`: main persistence abstraction
- `src/database/sqlite.ts`: schema definition and DB initialization

**Testing:**
- No `test/`, `tests/`, or colocated `*.test.*` files detected

**Documentation:**
- `README.md`: operator/developer quickstart
- `AGENTS.md`: agent-specific working rules
- `docs/SDD.md`: canonical architecture context

## Naming Conventions

**Files:**
- kebab-case with suffixes such as `*.service.ts`, `*.routes.ts`, `*.worker.ts`
- `app.ts` and `server.ts` are special entry/bootstrap files
- no colocated `index.ts` barrels detected in the app source

**Directories:**
- lowercase plural or role-based directories such as `routes`, `services`, `workers`, `schemas`

**Special Patterns:**
- route modules end in `.routes.ts`
- background/process helpers often end in `.worker.ts`
- environment/config docs stay at project root or under `docs/`

## Where to Add New Code

**New Feature:**
- Primary code: usually `src/routes/`, `src/services/`, and `src/database/repositories/`
- Tests: no established test location yet; a new `tests/` tree or colocated `*.test.ts` would need to be introduced deliberately
- Config if needed: `src/config/env.ts` and `.env.example`

**New Route/Endpoint:**
- Definition: `src/routes/`
- Supporting logic: `src/services/`
- Persistence: `src/database/repositories/`

**Utilities / Shared Types:**
- Shared types: `src/types/`
- Reusable domain helpers currently tend to live in `src/services/` or near the repository layer

## Special Directories

**`dist/`:**
- Purpose: compiled build artifacts
- Source: generated by `npm run build`
- Committed: effectively present in working tree; treat as generated output

**`data/`:**
- Purpose: mixed runtime state and reference fixtures
- Source: partially generated by the app, partially checked in as reference/debug material
- Committed: yes for some files, which means operational data can live beside source-controlled assets
